  Decisiones clave:
  - Record separa payload (los datos del evento) de la procedencia
    (source_file/line_number), así las reglas de limpieza/transformación solo
    ven datos reales, pero se puede trazar cualquier descarte hasta la línea
    exacta.
  - Cleaning vs Transformation: CleaningRule.keep() solo decide si se descarta
    un registro; TransformationRule.apply() solo normaliza valores, nunca
    descarta. Cada carpeta de reglas (rules/) tiene un DEFAULT_RULES = [] listo
    para que añadamos reglas concretas más adelante, un fichero por regla.
  - Extracción tolerante: JSONLExtractor recorre *.jsonl recursivamente y pone
    en cuarentena (log + skip) las líneas con JSON corrupto — ya detecté que
    data/ tiene bastantes líneas malformadas (comillas sin cerrar, claves sin
    comillas, etc.), separado de las reglas de negocio de limpieza.
  - Tabular: devuelve dict[str, DataFrame] en vez de una sola tabla, para poder
    partir por tipo de evento o añadir tablas de dimensión (p.ej.
    data/publishers.csv) sin tocar la capa de escritura.
  - Writing: intercambiable vía --format csv|parquet.

● I've added the ts format check as the first cleaning rule, and each run now
  writes metrics.csv (with your 10 columns) plus rejected.jsonl to the output
  folder. The 17 tests pass. Running uv run taptap-codetest --input data
  --output <out> on the real data gives 5,444 rows in metrics.csv and 22
  rejected lines.

  Accepted ts formats (timeutils.py):
  - ISO-8601 ending in Z, or with an explicit offset.
  - Epoch milliseconds, as a number or as a string of digits.
  - YYYY-MM-DD HH:MM:SS with no zone, read as Europe/Madrid time, so summer and
    winter time are both handled.
  - Anything else is rejected: ISO without a zone, other separators, impossible
    dates, booleans, empty strings. The rule itself is in
    cleaning/rules/timestamp.py, and a transformation rule uses the same parser
    to fill date_utc and hour_utc.

  rejected.jsonl: one object per discarded line, with reason, source_file,
  line_number and raw_line. Lines that aren't valid JSON go in it too (12 of
  them), since they are also discarded original lines. The other 10 are 6 with
  an empty ts and 4 with no ts.

  metrics.csv: one row per date, UTC hour, country and publisher. publisher_name
  comes from publishers.csv in the input folder.
  - ctr is clicks divided by impressions, and 0 when there are no impressions.
  - spend_eur is the sum of price_micros over impressions, divided by 1,000,000.
    That assumes price_micros is already in euros.

  Interface changes and fixes:
  - Each cleaning rule now returns the reason for dropping a record (or None to
    keep it), and each Record keeps its original line so it can go into the
    rejected file.
  - I fixed a bug: the extractor used to search --input recursively, so with
    --output data/output the next run would have read rejected.jsonl back in as
    events. It now reads only the top level of --input.

  Things you should know before the next rules:
  - data/events-test.jsonl (the file you have open) is in data/, so it gets
    processed. Its 30 lines are copies of real events and are counted twice.
    Move it out if it's just a test file.
  - Some timestamps pass the format check but make no sense: 0, -1,
    1970-01-01T00:00:00Z and 2099-04-11.... That's why rows dated 1969 and 1970
    appear. Rejecting them would be a separate date-range rule.
  - country comes in dirty (" DE ", "it", "ESP"), so the same country is split
    across several rows.
  - event_type has variants (BID_REQUEST, Impression, imp) that aren't counted
    yet.
  - price_micros has text values ("N/A", " 508500 ", "627.9e3", "1.2.3"). For
    now the table layer turns those it can't read into a number into 0; a proper
    rule should handle them.

  The next rules would be the date range for ts, then cleaning up country,
  event_type and price_micros.
